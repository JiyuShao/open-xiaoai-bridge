# 04: 原生小爱与小爱豆包的混合唤醒路由

Status: ready-for-agent
Execution: completed-mock (2026-10-29); real-acoustics-device-pending; silent-tests-only

**Parent:** [小爱豆包 spec](../spec.md)

**What to build:** 同一个 Bridge 中，“理想同学”走原生唤醒，“豆包豆包”走小爱豆包，并保留原厂“小爱同学”事件入口。以合成或文件音频和假 Client 验证分流，不连接真实设备。

**Blocked by:** 01 小爱豆包文字对话与默认会话。

依据：小爱豆包 spec、第二份 ADR。当前 `NATIVE_WAKE_ENABLE` 互斥规则和外部对话暂停 KWS 的行为不满足新目标，需明确迁移；用户同意调整该开关。纯原生运行应继续可验证，现有生产配置不在本任务中变更。

- [x] 明确纯原生/混合模式及旧开关的迁移规则，命令行、容器、准备模型和检查入口使用一致语义。
- [x] 配置非法或缺少必要资源时在设备连接前失败，不通过删除校验来任意混用后端。
- [x] 同一 Bridge 中两个自定义关键词分流准确，“豆包豆包”词表和检测链路可由文件音频验证。
- [x] 豆包等待用户讲话时仍可检测“理想同学”并切回原生，原生待机时可进入豆包。
- [x] 原厂小爱唤醒事件继续作为外部聊天的中断入口，不将自定义关键词推断为设备事件。
- [x] 单一生命周期与设备状态来源得到保留，避免复用控制事件时产生平行会话状态机。
- [x] 以假 Client 验证路由和请求次数，测试传输不执行 shell 或播放音频。
- [x] 纯原生启动/唤醒回归通过，旧配置迁移和混合模式独立记录验证结果。
- [x] 自定义词在真实播报期间的可靠打断和声学识别率明确不列为本任务通过保证。


## Comments

2026-10-29：新增 `WAKE_MODE=legacy|native|mixed`，未指定时兼容旧原生开关，冲突组合在配置导入/设备连接前失败。混合模式只支持原生 + OpenAI-compatible Hermes，统一命令行、脚本、关键词准备、容器与离线预检语义；默认使用双词路由与本地 SenseVoice。主循环仍为 MainApp.loop，现有 WakeupSessionManager 持有对话任务；短切换锁、停止并等待旧会话清理后再原生唤醒，不重建重复豆包会话。仅在用户讲话等待窗口恢复 KWS；原厂空唤醒标记仍作为中断入口，普通原生 ASR 指令透传。KWS/VAD 的 Silero 循环状态独立，混合模式启动前同步加载模型，失败/退出释放线程与音频 reader。混合模式不热重载路由/模型配置，修改须重新启动并预检。

验证：完整本地回归 133 项，130 通过、3 项真实服务测试跳过。新增模块与入口的 mypy 检查通过；修改的旧核心模块与 HEAD 对照，保留既有 23 项类型错误，未增加错误。compileall、bash 语法和 diff 检查通过。两轴审查最终 Standards 0 项、Spec 0 项；审查发现的脚本大小写/首尾空白语义差异已经补充先失败后通过的入口回归。另复现并修复 VAD 结果排队与助手切换同时发生时向已取消 Future 写结果的竞态，回调只在所属循环确认本轮 Future 未结束后交付。

证据范围：应用入口测试覆盖两个自定义词、重复唤醒、原生/豆包反复切换、VAD 回调恢复、普通原生指令透传；模拟 HTTP/ASR/TTS 轮次验证播放时自定义词不切换、原厂事件停止当前 token 并恢复录音，模型请求只有一次。启动子进程测试覆盖双词生成、缺文件、非法配置、模型初始化/设备服务失败以及线程/reader 释放。新增 `scripts/check_mixed_wake_audio.py` 可用实际模型对文件进行纯收集验证，不导入设备服务；自动化文件测试使用合成帧 WAV 与确定性模型替身，验证读取、检测线程、派发出口和两类路由。当前本机没有真实模型/语音样本，未执行真实声学文件验收，不能据此声称识别率或真机效果已通过。
