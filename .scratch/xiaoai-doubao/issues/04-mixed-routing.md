# 04: 原生小爱与小爱豆包的混合唤醒路由

Status: ready-for-agent

**Parent:** [小爱豆包 spec](../spec.md)

**What to build:** 同一个 Bridge 中，“理想同学”走原生唤醒，“豆包豆包”走小爱豆包，并保留原厂“小爱同学”事件入口。以合成或文件音频和假 Client 验证分流，不连接真实设备。

**Blocked by:** 01 小爱豆包文字对话与默认会话。

依据：小爱豆包 spec、第二份 ADR。当前 `NATIVE_WAKE_ENABLE` 互斥规则和外部对话暂停 KWS 的行为不满足新目标，需明确迁移；用户同意调整该开关。纯原生运行应继续可验证，现有生产配置不在本任务中变更。

- [ ] 明确纯原生/混合模式及旧开关的迁移规则，命令行、容器、准备模型和检查入口使用一致语义。
- [ ] 配置非法或缺少必要资源时在设备连接前失败，不通过删除校验来任意混用后端。
- [ ] 同一 Bridge 中两个自定义关键词分流准确，“豆包豆包”词表和检测链路可由文件音频验证。
- [ ] 豆包等待用户讲话时仍可检测“理想同学”并切回原生，原生待机时可进入豆包。
- [ ] 原厂小爱唤醒事件继续作为外部聊天的中断入口，不将自定义关键词推断为设备事件。
- [ ] 单一生命周期与设备状态来源得到保留，避免复用控制事件时产生平行会话状态机。
- [ ] 以假 Client 验证路由和请求次数，测试传输不执行 shell 或播放音频。
- [ ] 纯原生启动/唤醒回归通过，旧配置迁移和混合模式独立记录验证结果。
- [ ] 自定义词在真实播报期间的可靠打断和声学识别率明确不列为本任务通过保证。
