# 05: 原生操作由小爱豆包反馈并正确让出播放

Status: ready-for-agent
Execution: completed-mock (2026-10-29); real-hermes-device-pending

**Parent:** [小爱豆包 spec](../spec.md)

**What to build:** 豆包对话中调用原生能力后，由 Hermes 用当前声音要求反馈；短操作后继续聊天，音乐等持续播放由豆包让出音箱。助手切换不会触发重复操作或旧回复串入新会话。

**Blocked by:** 02 Vivi 自动播报与模型判断的阶段声音偏好；03 xiaoai-bridge 原生指令与操作记录闭环；04 原生小爱与小爱豆包的混合唤醒路由。

依据：小爱豆包 spec、第二份 ADR。反馈归属跟随发起入口：豆包发起用 Hermes/Vivi，原生入口继续原生反馈。请求受理不是业务完成。所有行为先通过假音箱和音频测试输出验收，不连接真实设备。

- [x] 豆包操作返回流经 Hermes 后自动反馈；原生 TTS 与 Hermes TTS 不并行双重播报。
- [x] 只有受理信息时清楚说明已提交但无法确认，不制造闹钟建立、灯已打开等成功结论。
- [x] 短操作完成当前反馈后继续等用户讲话，失败或超时不阻断以后新的有意请求。
- [x] 持续播放明确协调反馈与启动顺序，反馈后让出音箱并暂停交互；随后不自动插入提示音、唤醒或采音动作打断音乐。
- [x] 再次叫豆包可恢复默认聊天上下文；不自动重放之前的音乐或其他操作。
- [x] 原厂小爱事件中断豆包播报时停止对应播放，避免无 token 全局停止误伤后续会话。
- [x] 切换/取消后迟到的模型回复、工具结果与旧播放任务不会覆盖新会话，操作审计仍保留真实状态。
- [x] 切换过程中已提交的操作不重发，超时结果未知仍按未知记录。
- [x] 测试从对话入口检查输出次序、传输次数、音乐让出和日志，不只检查私有函数是否被调用。
- [x] 原生静默执行与真实播放器控制权仍需真机验证，Mock 通过不冒充实际完成。
