# 03: xiaoai-bridge 原生指令与操作记录闭环

Status: ready-for-agent

**Parent:** [小爱豆包 spec](../spec.md)

**What to build:** 小爱豆包通过本项目的 `xiaoai-bridge` skill 提交原生指令，获得准确的受理、拒绝或未知结果，并查询持久化操作记录。统一迁移原有播放控制入口，测试中由假音箱执行协议应答。

**Blocked by:** 01 小爱豆包文字对话与默认会话。

依据：小爱豆包 spec、第二份 ADR。优先复用已有 `ask_xiaoai` 和播放原语；不直接接 HA，不向 Agent 开放 shell。所有实际设备调用均替换为测试传输，生产音箱与生产工具不可达。

- [ ] 本项目创建 `xiaoai-bridge` skill，提供原生命令及已有必要播放、状态、打断和唤醒能力，迁移现有 `xiaoai-tts` 入口及引用。
- [ ] 经受控接口提交自然语言指令，工具调用不会把任意 shell 能力暴露给模型。
- [ ] 文本含单引号、换行及 shell 特殊字符时能保持原意传输，不形成命令注入。
- [ ] 豆包原生指令以静默反馈目标提交，返回准确区分受理、拒绝、超时及未知；无业务证据时不能报告完成。
- [ ] 静默原生参数在 Mock 中可验证；真实抑制效果和原生结果采集能力明确保留为设备待验项。
- [ ] 操作以请求标识关联；重复投递不重复执行，超时或重启后未知状态不自动重放，新的有意操作不被误去重。
- [ ] 操作前后状态、实际返回及错误持久化保存，重启后可查询；业务完成证据与模拟结果明确区分。
- [ ] 记录时间、session、指令、参数、受理情况、返回、错误和确认程度；凭据不进入记录，不额外保存聊天录音。
- [ ] 测试工具仅指向假音箱 API，真实 Hermes 验证也必须使用专用 profile 和受限工具集合。
- [ ] 测试覆盖成功应答、拒绝、超时、重复、异常中断和恢复后的下一次有意操作。
