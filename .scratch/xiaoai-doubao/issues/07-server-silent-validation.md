# 07: Docker 服务器隔离静默验收

Status: ready-for-agent

**Parent:** [小爱豆包 spec](../spec.md)

**What to build:** 在 Docker 服务器上运行完整的小爱豆包测试链路，先 Mock、后按可用凭据加入真实 Hermes 和仅生成文件的豆包合成；输出可复查的测试报告，生产音箱与服务不受测试控制。

**Blocked by:** 05 原生操作由小爱豆包反馈并正确让出播放；06 文件语音进入小爱豆包并验证现有 ASR。

依据：小爱豆包 spec、第二份 ADR。用户允许在现有 Docker 服务器上研究静默测试，但未允许真实音箱发声、生产部署/重启或真实设备命令。测试环境须独立，不能将已有只覆盖原生模式的验证编排直接视为具备新功能。

- [ ] 独立 Compose 项目、容器、端口、网络、凭据、session、产物和日志目录，与生产环境无共享控制入口。
- [ ] 假 Client 扩展处理对话、播放和原生命令协议，所有命令只记录和应答，绝不执行设备命令或启动播放器。
- [ ] 从测试 Bridge、测试 Agent 和工具执行环境验证无法访问真实音箱及生产 Bridge，而不只检查端口绑定或配置中的静默开关。
- [ ] 测试 Agent 不继承生产工具、远端 shell、生产秘密、宿主机 Docker 控制和任意设备访问能力。
- [ ] Mock 全链路覆盖聊天、阶段偏好、原生操作、结果未知、去重、助手切换、持续播放让出、错误恢复和日志持久化。
- [ ] 具备专用 Hermes 与凭据时运行真实对话与工具场景；否则明确标记待测，不擅自复用生产权限。
- [ ] 具备 TTS 凭据时合成音频只落文件；缺少凭据时仍完成协议与 Mock 验证，不计为真实合成成功。
- [ ] 测试环境停止/重建后检查会话、审计和产物的恢复行为，结果未知操作不自动执行。
- [ ] 生产容器、配置和真实 Client 连接不被测试修改或重启；任何可能发声的路径都不执行。
- [ ] 报告区分离线、服务器 Mock、真实 Hermes、真实 TTS 和尚未进行的设备/声学/试听验收，列出失败与限制。
- [ ] 真机验证留待用户明确允许，未验证真实设备不阻止诚实交付静默阶段成果。
