# 04: 在目标服务器验证真实关键词检测运行

**What to build:** 用户现有的 Docker 服务器能够在容器内运行固定版本 Bridge，通过测试录音识别新词，并在不连接真实音箱时验证原生唤醒请求。

**Blocked by:** 02: 统一启动与离线检查，使原生模式可重复启动

**Status:** ready-for-agent

- [ ] 确认现有 Docker 服务器的系统、架构、Docker/Compose 版本与资源，获得对应访问与部署授权；只索取尚缺信息，不在聊天收集凭据。
- [ ] 构建并运行固定版本 Bridge 容器，明确模型/配置挂载、网络与重启策略，准备匹配的 KWS/VAD 模型，记录版本与摘要，不引入全文 ASR 或外部 AI。
- [ ] 通过匹配采样率的真实测试录音覆盖包含和不包含目标词的情况；真实模型推理结果与假传输结果分别记录。
- [ ] 私有 Token 通过受控配置提供，连接受限；通过假 Client 验证连接鉴权和唤醒请求，不操作真实设备。
- [ ] 验证停止与重启，给出可重复启动/停止方法；录音不能代替真机声学验收。
