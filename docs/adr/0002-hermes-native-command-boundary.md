# 小爱豆包自动播报聊天回复，操作优先委托原生小爱

Status: accepted

用户确认新增“豆包豆包”入口，对应 Hermes profile `xiaoai-doubao`，展示名称“小爱豆包”，先使用一个默认人格和默认会话。它与“理想同学”及原厂“小爱同学”的原生入口在同一个 Bridge 中共存，需要调整当前 `NATIVE_WAKE_ENABLE` 的严格互斥设计；具体开关及迁移方式尚待设计，不视为已实现。

普通聊天直接交给 Hermes，最终回复由 Bridge 自动合成并播放，默认选择豆包 Vivi 2.0。操作请求优先委托原生小爱，不把普通聊天也转交原生小爱；HA 直接接入留待后续讨论。选择复用原生能力，以保留已有小米功能的执行路径，代价是原生系统可能不能提供可核实的业务完成状态。

本项目将以 `xiaoai-bridge` skill 统一封装原生命令与播放控制，不再保留独立的 `xiaoai-tts` skill 入口。底层音箱 shell 不作为 Agent 工具开放。所有操作及结果均须记录；超时或结果未知时不自动重试，不将请求受理描述为业务完成。

反馈归属由发起请求的助手决定：通过“豆包豆包”发起的操作，由 Hermes 使用 Vivi 回复；原生入口发起的操作继续由原生小爱反馈。因此豆包路径需要协调原生播报与 Hermes 播报，不能简单并行播放。现有 `ask_xiaoai()` 仅返回请求受理信息，静默调用、原生结果采集和关联能力仍需验证；这里记录的是目标行为，不代表已能获得业务完成证据。

用户确认普通对话使用亲切、自然、简洁的默认人格，情绪随语境适度变化，用户明确要求优先。默认会话跨次延续；结合上一轮确认，目标是重启后可恢复，显式开启新对话时开始新上下文，同一音箱暂共用一个会话。Vivi 合成不可用时允许回退到原生小爱音色并记录原因，不保证回退后情绪、语种和方言效果一致。

用户进一步要求由大模型根据聊天语境动态判断情绪、语种和方言，不将声音切换限制为显式设置偏好，用户明确要求优先。拟由 Hermes 每轮提供回复文字及本轮声音要求，Bridge 校验后自动调用 TTS；这仍属于自动播报，不要求 Agent 每轮调用播放工具。声音要求的具体返回协议、能力不支持时的处理规则仍待设计与验证；不能视为现有 Hermes 接口已提供结构化声音字段。

用户进一步限定首版只做阶段偏好：声音要求只在当前会话的一段交互中生效，不作为长期用户偏好保存。用户确认根据大模型对当前 session 的记忆判断偏好是否仍然有效，而非每次语音交互结束就强制清除；用户明确指定的要求始终优先，模型判断自然延续或阶段结束。单句要求只覆盖当句，开启新会话不继承旧会话声音偏好。默认聊天会话的延续与声音偏好的有效期分别处理。

原生命令只取得受理信息时，Hermes 应明确说明已提交但结果未确认，不假称操作完成。持续播放音乐时，Hermes 简短反馈后让出音箱并暂停本次语音交互，重新唤醒豆包后沿用默认聊天会话；短操作反馈后继续聊天。

首版切换目标为：豆包等待用户讲话时，“理想同学”切回原生小爱；原生入口待机时，“豆包豆包”进入 Hermes；豆包播报时先使用原厂“小爱同学”打断。原生操作执行途中切换助手，不自动重发该操作。这需要调整现有外部对话期间暂停 KWS 的行为，不能视为已有功能；播报中自定义词打断不列为当前保证。

操作记录包含时间、会话、操作指令、调用参数、受理情况、返回结果、错误和是否确认完成，重启后保留，直到用户主动删除；不记录凭据，也不因操作审计额外保存整段聊天录音。输入侧首版确保普通话可用，英语、四川话先复用已有 ASR 实测，记录效果后再决定是否更换识别服务，不作为首版必须达到的识别指标。输出侧验证 Vivi 对应语种、方言和情绪控制；更广范围仍需单独确认。

2026-10-28 用户明确要求实施期间暂不触发真实音箱声音，原因是宝宝正在睡觉。在用户另行允许真机发声前，只进行本地实现、Mock 和静默检查，不调用真实音箱控制或播放接口，不重启可能触发连接、启动或会话提示音的服务。声音相关测试使用替身或仅生成不播放的音频文件；本次设计讨论不授权生产部署或设备操作。

静默检查可以在 Docker 服务器的独立测试环境中运行：使用独立 Bridge、假 Client、测试凭据和测试结果目录，不连接或替换真实 Client，不修改或重启生产服务。现有 `tests/native_wake_runtime.py` 已具备仅应答、不执行设备命令的假 Client，但它只验证原生唤醒，尚不覆盖新对话和播放协议，需要扩展。测试 Agent 只能使用指向测试 API 的 `xiaoai-bridge`，不得继承生产工具及设备控制权限；需隔离其对真实音箱和生产 Bridge 的访问。默认使用 Mock Hermes/TTS；在相应服务与凭据可用时，才增加真实 Hermes 对话及仅保存音频文件的 TTS 合成测试，绝不播放。模拟结果不能作为原生操作已在设备完成的证据。

本记录只确认上述已达成的设计边界。实现与部署需在设计访谈完成后进行，现有原生唤醒及常驻记录文档的执行状态不因此改变。
